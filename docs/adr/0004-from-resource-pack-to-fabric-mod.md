# 从资源包转向 Fabric 客户端模组

## Status

accepted

## 背景与决定

资源包版本（v0.2.1）做到了"完全隐藏"，但受机制天花板限制：无法阻止邻居面被剔除（雪地等出现大片洞）、无法让隐藏方块不再遮挡光照、改一次清单要重新打包并在游戏里切换。实机测试后确认这些限制无法靠资源包继续缓解。因此把交付形态改为 **Fabric 纯客户端模组**：在渲染层跳过隐藏方块的绘制，并修改剔除判定（只在邻居被隐藏时反转）、选择性修改光照输入，从而得到资源包做不到的"无洞 + 光照 + 即时切换"。

## Considered Options

- **继续做资源包**：零构建链、跨版本容易，但洞、光照、即时切换都无解；已到天花板。
- **资源包 + OptiFine/Iris 特性**：仍不能改剔除；光照 lightmap 只在 OptiFine 生效，且用户已选零依赖。
- **服务端模组**：能改玩法判定，但需要服务端安装，超出"自己看地形"的需求，且多人服务器不可控。
- **Fabric 纯客户端模组**（采纳）：只需客户端；1.21.11 生态成熟（Loader 0.20.1 / Fabric API 0.141.6 / Yarn build.6 / Loom 1.12 已在本机验证），且有 Xray/Meteor 等开源先例可复用思路。

## Consequences

- 需要长期维护构建链（Gradle/Loom/Yarn/Fabric API）与版本适配；资源包时代不需要。
- 1.21.11 是最后一个混淆版本；26.x 起去混淆 + Java 25，客户端模组不能跨版本通用，跟版要单独做。
- 资源包工程归档为 `_legacy-pack-export/`（tag `pack-legacy-v0.2.1`），不再是交付物；`data/blocks.json` 的分类清单被 `data/default-blocks.json` 沿用。
- 光照首版采用顶点亮度/AO 提亮（不真 relight），因为客户端 relight 可能被服务端 light 包覆盖；这是可感知的折中。
- 风险集中在新版本渲染重构后的 mixin 签名、VisGraph 整段剔除、Sodium/Iris 共存；需要实机试验。
